# Steam-free macOS and iPhone checks

`.github/workflows/macos-check.yml` is an on-demand, game-free integration workflow. It runs when requested from
the Actions tab and on the disposable `ci/macos` branch. The dispatch form enables Apple Silicon by default and
offers Intel as a separate opt-in. No job receives a secret, repository variable, environment, Steam tool, game
download, or self-hosted runner.

This document is the contract for reading a green run. It intentionally separates a useful hosted result from
claims that still need a player-owned installation or physical device.

## What each leg proves

| Leg | A green result proves | It does not prove |
| --- | --- | --- |
| Hosted Mac package, on each selected architecture | Both pinned reference-SDK lanes restore in locked mode; the production snapshot package builds with stock macOS Bash/BSD tools; its exact-case, spaces-in-path layout and metadata dependency closure match the release allowlists. | The game discovers the mod, Godot loads it in the host process, or the package still opens after modifying a signed `.app`. |
| Hosted Mac Harmony smoke | The pinned public Harmony runtime can patch and invoke a trivial CouchCoop-owned method in a standalone process, and the watchdog recognizes success, non-zero exit, crash/signal, and timeout. | Harmony can patch a game method inside the signed game process. |
| Stable/public-beta target metadata | The declaration-only reference DLLs still contain both supported lobby screen types with a directly declared, zero-argument `_Ready`; the check reads PE metadata and never loads those DLLs. | That either reference lane can execute, or that the runtime game has identical behavior. |
| Godot .NET lobby-hook fixture, on each selected architecture | The exact production mount-hook implementation can patch two synthetic Godot `Control` types with public Harmony 2.4.2, dispatch each callback once, remain idempotent, and stay alive for at least 30 frames and five seconds. | Mod discovery, actual STS2 scene identities, the QR panel's real resources/layout, or Harmony inside the signed game process. |
| Ad-hoc hardened Godot .NET fixture | The same synthetic hook succeeds after a temporary Godot copy is ad-hoc signed with hardened runtime and the reviewed JIT/dynamic-loading entitlements. | Developer ID signing, notarization, Gatekeeper acceptance, or the entitlement set used by the real game. |
| Playwright WebKit, iPhone 13 profile | WebKit can load both the frozen baseline and deterministic field-reproduction workloads, preserve a single visit/journey, acknowledge every credit-gated keyframe/delta, and remain responsive for ten seconds plus 30 frames after the final delta. | Simulator Safari integration, physical iPhone memory/GPU pressure, or Jetsam behavior. Playwright's device profile is emulation, not an iOS runtime. |
| Simulator SafariDriver, exact iPhone 13 | On Apple Silicon, Safari in the selected exact iPhone 13 Simulator survives the field-reproduction workload and no matching bounded Safari/WebKit crash header appears in the test window. A capability result records when the exact device/runtime or SafariDriver is unavailable; another model is never substituted. | A physical iPhone, real radio/network conditions, genuine memory pressure, physical-device thermal pressure, or physical-device Jetsam behavior. |
| Physical-iPhone report | Only an actual field report can cover device RAM/GPU limits, Jetsam, temperature, local-network permissions, and the installed iOS/Safari build. | Mac host discovery, Godot, Gatekeeper, or Harmony in the game. |

Hosted CI never downloads or launches Slay the Spire 2. No game binary, game asset, captured gameplay payload,
real screenshot, or recording enters GitHub through this workflow. The scene text, controls, textures, and PNGs
are generated by the test harness at runtime.

## Running the checks

The normal hosted path is **Actions → macOS check → Run workflow**. `run_arm` defaults to true; enable
`run_intel` only when an Intel result is needed. Both selected Mac jobs wait for the Ubuntu workflow-policy and
hermetic WebKit gates. The exact iPhone Simulator leg is Apple-Silicon-only; Intel still exercises package,
reference-metadata, standalone Harmony, stock Godot .NET, and ad-hoc hardened Godot .NET coverage.

Local game-free equivalents are:

```bash
dotnet run --project tests/CouchCoop.MacOs.Tests -c Release
scripts/verify-sts2-reference-sdk.sh stable public-beta
scripts/test-verify-release-archive.sh
PLAYWRIGHT_HTML_OPEN=never npm --prefix frontend run test:iphone-webkit
scripts/test-iphone-safari-simulator.sh
scripts/test-validate-iphone-artifact-stage.sh
scripts/test-macos-iphone-workflow-policy.sh
```

The package command itself is `scripts/package-release.sh --snapshot`. It deliberately requires clean CouchCoop,
`spirectl`, and `godot-scene-web` checkouts and creates a local `dist/` archive. Do not commit or upload that
archive.

### Optional real-server WebKit observation

The dedicated iPhone WebKit suite is hermetic by default. Real-server mode is local-only and requires both
opt-ins:

```bash
COUCHCOOP_E2E_REAL_URL='http://127.0.0.1:8080/?seat=2' \
COUCHCOOP_ALLOW_REAL_GAME=1 \
PLAYWRIGHT_HTML_OPEN=never \
npm --prefix frontend run test:iphone-webkit
```

This mode starts no game, server, deployment, Steam command, or discovery process. It may choose a host/seat only
through the semantic picker and never drives gameplay. It reports query **key names**, not values. It refuses to
run in GitHub Actions.

No real-mode artifact is written by default. To opt into local evidence, set
`COUCHCOOP_E2E_LOCAL_EVIDENCE=1`; all output is forced beneath
`.sts2/research/playwright-iphone-webkit/` and must be treated as potentially proprietary. That directory is
local research state and must never be committed or uploaded by the hosted workflow.

## Browser diagnostics and hosted artifacts

The lifecycle channel does not exist during ordinary play. The synthetic harness enables it by passing a
validated artifact directory; the page receives only a same-origin relative endpoint and per-visit nonce, never
the filesystem path. Accepted records are bounded, schema-checked, redacted lifecycle/checkpoint data. URLs,
query values, player names, payloads, stacks, user agents, tokens, and arbitrary messages are rejected rather
than scrubbed after collection.

Hosted uploads contain only explicitly staged synthetic/sanitized result, timeline, lifecycle, crash-header, or
failure-screenshot files, retained for three days. The release archive, restored SDK, browser build directory,
Simulator diagnostic tree, and external paths are not staged. Download a run's artifact from its **Artifacts**
section on the Actions run summary; the workflow-policy test treats any new upload path as a reviewed allowlist
change.

The field-reproduction profile is deterministic: seed `20260918`, 1,025 scene nodes, 256 text nodes and distinct
characters, 80 generated PNG resources, 100,941,824 decoded RGBA bytes, 1,024-pixel maximum dimensions, two
keyframes, four deltas, and six real presentation acknowledgements. The original baseline remains frozen at 92
nodes, 67 text nodes, 204 distinct characters, 24 PNGs, 279,552 decoded RGBA bytes, one keyframe, one delta, and
two acknowledgements. These are bounded synthetic workloads, not claims about physical-device memory pressure.

## macOS support report

Run the read-only support helper with explicit paths:

```bash
scripts/macos-support-diagnostics.sh \
  --app '/Applications/SlayTheSpire2.app' \
  --mod '/Applications/SlayTheSpire2.app/Contents/MacOS/mods/couchcoop' \
  --log "$HOME/Library/Application Support/SlayTheSpire2/logs/godot.log"
```

It prints redacted OS/architecture and locations, the `release_info.json` version, allowlisted package-layout
verdicts, hashes/modes for allowlisted CouchCoop files, summarized `codesign`/`spctl` outcomes, and only anchored,
fully validated CouchCoop checkpoint lines. Besides the loader/version/payload/invoke/init and Harmony-probe
records, the allowlist covers bounded lobby patch attempts/results, listener availability, controller arming,
the two supported lobby kinds, host-state classification, and QR-panel installation entry/result. It writes
nothing into the app and neither copies nor walks arbitrary game content; URLs, ports, paths, player data,
exceptions, stack traces, unknown enum values, and arbitrary suffixes are rejected.

Interpret the last bounded checkpoint as follows:

- No `loader-entry`: the bootstrap was not discovered or invoked.
- `loader-entry` without `loader-invoke`: lane selection, payload validation, or bootstrap handoff stopped first.
- Failed Harmony probe or an exhausted lobby patch: native patching was refused or no supported mount callback
  remained; there is no fallback hook.
- Lobby mounted with `result=unavailable` or `result=not-host`: the hook ran, but readable state did not identify a
  host lobby.
- `result=host` followed by `qr-panel-install-failed`: the bounded category identifies the failed install stage.
- `qr-panel-install-complete`: the panel attached and survived initial activation. Check listener availability
  separately because the panel intentionally installs even when the listener is unavailable.

These checkpoints establish bounded control-flow evidence only. They do not prove correct visual rendering,
real-game scene compatibility, post-modification Gatekeeper behavior, or Harmony inside the signed game.
